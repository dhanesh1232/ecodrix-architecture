## Implemented this pass

**`laie_tenants` Tenant_Shadow demotion — finish the incomplete cutover.**

`shared/db/schema/laie/tenant.schema.ts` now only carries `id`, `name`,
`createdAt` (status/plan/settings moved to the platform layer). Two API-gateway
middleware files still referenced the dropped columns, which **failed
`tsc`** (9 errors):

- `services/api-gateway/middleware/auth.ts` — `validateApiKeyInDb` selected
  `tenants.status` / `tenants.plan`. Rewired the query to left-join
  `ecodrix_organizations` (status, `id == laie_tenants.id`) and `ecodrix_plans`
  (slug → plan), defaulting to `active` / `free`. This matches how
  `routes/admin.ts` was already migrated.
- `services/api-gateway/middleware/tenantResolver.ts` — removed the
  `tenant.status` / `cached.status` re-validation (status is owned by the
  platform layer and already enforced by `authMiddleware`) and the
  `result.plan` log field.

`routes/laie/lead-preferences.routes.ts` and `routes/laie/profile.routes.ts`
each had a Drizzle `.values(Record<string, unknown>)` insert that lost the
`orgId` required-field guarantee — cast to `typeof table.$inferInsert`.
